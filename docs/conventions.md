# 코드 작성 규칙

6개월 뒤의 나와 옆자리 동료가 코드를 찾고 이해할 수 있게 만드는 것이 목적입니다.

지켜야 할 것은 세 가지입니다.

1. **이름을 규칙대로 짓기** — 분류·내용·작성자가 파일명에 드러나야 합니다.
2. **머리말 달기** — 입력·출력·주의사항을 코드 맨 위에 적습니다.
3. **README 표에 한 줄 남기기** — 코드 목록과 주의사항 표를 갱신합니다.

## 1. 파일 이름

### 공통 원칙

- 전부 **소문자**로 씁니다.
- 단어 구분은 **밑줄**(`_`)로 합니다.
- **영문만** 사용합니다. 한글 · 공백 · 대문자는 쓰지 않습니다.
- **끝에 작성자 표시**를 붙입니다. 아래 규칙을 따릅니다.
- `v2` · `final` · `수정본` 같은 표시는 붙이지 않습니다. 버전은 Git이 관리합니다.

!!! danger "한글·공백 파일명이 위험한 이유"
    리눅스 서버 · 윈도우 · macOS가 한글을 서로 다르게 저장합니다.
    같은 이름인데도 서버에서 파일을 찾지 못하거나 스크립트에서 경로가 깨지는 일이 실제로 자주 생깁니다.

### 작성자 표시

**모든 코드 파일 이름 끝에** 작성자 표시를 붙입니다. 공용 코드와 팀 코드 모두 해당합니다.

```
… _<성><이름 이니셜>.py
```

| 이름 | 표시 | 파일 예시 |
|------|------|-----------|
| 홍길동 | `honggd` | `plot_map_asia_honggd.py` |
| 김철수 | `kimcs` | `101_calc_anomaly_kimcs.py` |
| 이영희 | `leeyh` | `io_read_era5_leeyh.py` |

- 성은 **영문 전체**, 이름은 **이니셜 두 글자**를 소문자로 붙입니다.
- 동명이인이 있으면 팀에서 구분자를 정해 README에 적어 둡니다.
- 여러 사람이 함께 쓴 코드는 **주 작성자 한 사람**만 표시합니다.

붙이는 이유는 세 가지입니다.

- 파일 목록만 보고 **누구에게 물어볼지** 바로 알 수 있습니다.
- 같은 목적의 코드를 여러 사람이 각자 만들어도 **이름이 충돌하지 않습니다.**
- 졸업·이직 후에도 **책임 소재가 남습니다.**

### basic-codes — 분류 접두어 방식

여러 사람이 아무 때나 코드를 추가하므로, **무엇에 관한 코드인지**가 이름 앞에 오도록 합니다.

```
<분류>_<대상>_<동작>_<작성자>.py
```

| 접두어 | 용도 | 예시 |
|--------|------|------|
| `io_` | 자료 읽기 · 쓰기 | `io_read_ssmi_bytemap_honggd.py` |
| `plot_` | 그림 그리기 | `plot_map_asia_honggd.py` |
| `calc_` | 계산 · 통계 | `calc_anomaly_kimcs.py` |
| `util_` | 잡다한 도구 | `util_latlon_to_index_leeyh.py` |
| `tut_` | 입문 노트북 | `tut_01_xarray_basics_honggd.ipynb` |

### team-* — 번호 방식

팀 코드는 **실행 순서**가 중요하므로 번호를 앞에 붙입니다.

```
<번호>_<대상>_<동작>_<작성자>.py
```

| 번호대 | 단계 | 예시 |
|--------|------|------|
| `0xx` | 자료 내려받기 · 전처리 | `001_era5_download_honggd.py` |
| `1xx` | 계산 · 분석 | `101_calc_anomaly_kimcs.py` |
| `2xx` | 그림 | `201_plot_map_leeyh.py` |
| `9xx` | 임시 · 실험 | `901_test_regrid_honggd.py` |

- 번호 사이를 띄워 두면(`001` · `010` · `020`) 나중에 중간 단계를 끼워 넣기 좋습니다.
- 위 번호대는 예시입니다. **팀마다 규칙을 정해 저장소 README에 적어 두세요.**

### 좋은 예 / 나쁜 예

| 좋은 예 | 나쁜 예 | 이유 |
|---------|---------|------|
| `io_read_era5_pressure_honggd.py` | `read.py` | 무엇을 읽는지, 누가 썼는지 알 수 없음 |
| `plot_map_asia_kimcs.py` | `그림그리기.py` | 한글은 환경에 따라 깨짐 |
| `calc_moving_average_leeyh.py` | `calc_MA_v2_final.py` | 버전은 Git이 관리함 |
| `101_calc_anomaly_honggd.py` | `분석2.py` | 순서도 내용도 알 수 없음 |
| — | `temp.py` · `test.py` | 임시 파일은 커밋하지 않음 |

## 2. 파일 머리말

모든 코드 맨 위에 아래 형식의 주석을 답니다.
README 표를 채울 때 이 내용을 그대로 옮기면 되므로 두 번 일하지 않습니다.

```python
"""
101_calc_anomaly_kimcs.py

기후값 대비 편차를 계산해 pickle로 저장.

입력   : ../data/era5_daily.nc
출력   : ../data/anomaly.pkl
의존   : numpy, xarray

주의   : 1991-2020 기후값 기준. 다른 기간을 쓰려면 CLIM_YEARS 를 수정할 것.
        메모리를 30 GB 정도 사용하므로 계산 노드에서 실행할 것.

작성자 : 김철수 (2026-09-03)
"""
```

노트북(`.ipynb`)이라면 **첫 셀을 마크다운으로 만들어** 같은 내용을 적습니다.

### 경로는 상단에 모읍니다

```python
# 경로 설정 — 환경에 맞게 수정
DATA_DIR = '/home/username/data'
OUT_DIR  = '../result'
```

코드 중간중간에 절대 경로가 흩어져 있으면 다른 사람은 실행조차 하지 못합니다.

## 3. README 표 갱신

각 저장소 README에는 표 두 개가 있습니다. **코드를 추가하거나 고치면 함께 갱신하세요.**

### 코드 목록

| 파일 | 한 줄 설명 | 작성자 | 최종 수정 |
|------|-----------|--------|-----------|
| `code/001_era5_download_honggd.py` | CDS API로 ERA5 기압면 자료를 내려받음 | 홍길동 | 2026-09-03 |
| `code/101_calc_anomaly_kimcs.py` | 1991-2020 기후값 대비 편차를 계산함 | 김철수 | 2026-09-05 |

- 한 줄 설명은 **동사로 끝내고 20자 내외**로 씁니다.
- "~하는 코드" 같은 군더더기는 붙이지 않습니다.

### 사용 시 주의사항

머리말에도 쓰지만, **남이 겪을 만한 함정**은 README에도 남깁니다.
파일을 열어 보기 전에 알 수 있어야 시간을 아낄 수 있기 때문입니다.

| 파일 | 주의사항 |
|------|----------|
| `001_era5_download_honggd.py` | CDS API 키가 `~/.cdsapirc` 에 있어야 함. 한 번에 5년 이상 요청하면 대기가 길어짐 |
| `101_calc_anomaly_kimcs.py` | 메모리 30 GB 이상 사용함. 로그인 노드가 아니라 계산 노드에서 실행할 것 |
| `plot_map_asia_honggd.py` | cartopy 0.22 미만에서 gridlines 라벨이 잘림 |

무엇을 적을지 막막하다면 아래를 떠올리면 됩니다.

1. 실행 전에 준비해야 하는 것 — API 키 · 자료 위치 · 디렉토리 생성
2. 자원 요구량 — 메모리 · 실행 시간 · 계산 노드 필요 여부
3. 버전에 따라 동작이 달라지는 부분
4. 하드코딩된 가정 — 기간 · 영역 · 격자 크기
5. 이미 알려진 버그와 우회 방법
