# 저장소 구성

연구실 코드는 **용도별로 저장소를 나누어** 관리합니다.
GitHub은 폴더가 아니라 저장소 단위로 권한을 부여하기 때문에, 저장소를 나누는 것이 팀별 접근 통제를 구현하는 방법입니다.

```
github.com/smlsnu/
├── home           안내 문서 (이 사이트)
├── basic-codes    공용 코드
├── team-rain      팀별 코드
├── team-tq
├── team-rt
├── team-polar
└── team-env
```

## home

연구실 GitHub 사용 규칙과 안내를 담습니다. **코드는 넣지 않습니다.**

- `docs/` 안의 마크다운을 고쳐 push하면 몇 분 안에 이 사이트에 반영됩니다.
- 각 페이지 우측 상단의 연필 아이콘을 누르면 해당 파일 편집 화면으로 바로 이동합니다.

!!! warning "유일하게 공개(public)된 저장소입니다"
    코드 · 데이터 · API 키를 이곳에 올리지 마세요.

## basic-codes

연구실 구성원이 공통으로 쓰는 코드를 모읍니다. `lab-members` 팀이면 누구나 추가 · 수정할 수 있습니다.

**올리는 것**

- 위성 · 재분석 자료를 읽고 쓰는 코드
- 지도 · 시계열 등 반복해서 쓰는 그림 템플릿
- 좌표 변환 · 날짜 처리 · 통계 유틸리티
- 신입 연구원용 입문 노트북

**올리지 않는 것**

- 특정 팀에서만 쓰는 분석 코드 — 해당 `team-*` 저장소에 둡니다.
- 한 번 쓰고 버릴 임시 코드

**폴더 구조**

파일은 저장소 최상위에 평평하게 두고, **이름 앞의 분류 접두어**(`io_` · `plot_` · `calc_` · `util_` · `tut_`)로 구분합니다.
코드가 충분히 쌓이면 그때 폴더로 묶습니다.

## team-*

팀별 분석 코드를 담습니다. 각 저장소는 같은 이름의 팀만 수정할 수 있습니다.

| 저장소 | 팀 |
|--------|-----|
| `team-rain` | `team-rain` |
| `team-tq` | `team-tq` |
| `team-rt` | `team-rt` |
| `team-polar` | `team-polar` |
| `team-env` | `team-env` |

### 폴더 구성

모든 팀 저장소는 같은 구조를 씁니다.

```
team-rain/
├── code/             분석 스크립트 · 노트북
├── result/           팀원끼리 공유하는 결과 그림
├── README.md         목적 · 자료 · 실행 순서 · 담당자
├── environment.yml   conda 환경
├── requirements.txt  pip 환경
└── .gitignore
```

**`code/`**

- 실행 순서를 알 수 있도록 번호를 붙이는 것을 권합니다.
- 예: `001_download_honggd.py` · `101_calc_anomaly_kimcs.py` · `201_plot_map_leeyh.py`

**`result/`**

그림만 커밋할 수 있습니다.

| 확장자 | 결과 |
|--------|------|
| `.png` `.jpg` `.gif` `.svg` `.pdf` | 허용됨 |
| `.pkl` `.h5` `.nc` `.npy` 등 데이터 | 차단됨 |

!!! warning "용량 주의"
    - 한 파일 **100 MB 초과**는 GitHub이 거부합니다.
    - 저장소 전체도 **1 GB 이내**를 권장합니다.
    - 같은 그림을 다시 그렸다면 새 파일을 추가하지 말고 **덮어쓰세요.** 이전 버전은 Git 이력에 남습니다.

### README에 반드시 포함할 것

1. 팀의 연구 목적 · 대상 영역 · 기간
2. 팀장과 구성원
3. 사용 자료의 종류 · 기간 · 획득 방법
4. **팀에서 정한 파일 이름 규칙**
5. 기준 실행 환경 (conda 또는 pip)
6. 코드 목록 표와 사용 시 주의사항 표

### 새 팀 추가

조직 Owner에게 요청하세요. 아래 순서로 처리됩니다.

1. `smlsnu/team-<이름>` 저장소 생성
2. `team-<이름>` 팀 생성 → 해당 저장소에 Write
3. `lab-members` 팀 → 해당 저장소에 Read
4. 이 사이트의 저장소 목록에 추가

## 코드 작성 규칙

- 파일 이름 규칙, 머리말 양식, README 표 갱신 방법은 [코드 작성 규칙](conventions.md) 에 정리했습니다.
- 실행 환경 구성은 [실행 환경](environment.md) 을 참고하세요.

## 그 밖의 권장 사항

**파일 상단에 목적을 밝힙니다**

무엇을 하는 코드인지, 어떤 입력이 필요한지를 주석으로 남깁니다.

**절대 경로는 변수로 모읍니다**

```python
# 경로 설정 — 환경에 맞게 수정
DATA_DIR = '/home/username/data/ssmi'
OUT_DIR  = '/home/username/result'
```

**데이터는 함께 올리지 않습니다**

어디서 받는 자료인지 주석으로 설명하고, 파일 자체는 커밋하지 않습니다.
